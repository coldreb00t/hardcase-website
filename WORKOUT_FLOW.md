# 🏋️ Workflow программ тренировок

## Обзор бизнес-логики

### Концепция

**Тренер** всегда онлайн во время тренировки клиента и следит за выполнением в реальном времени.  
**Клиент** видит программу заранее и отмечает только субъективные ощущения (RPE).

---

## 📋 Роли и обязанности

### **👨‍🏫 Тренер:**

#### **До тренировки:**
1. Создаёт программу через `ProgramConstructor`
2. Указывает для каждого упражнения:
   - Название
   - Целевые подходы
   - Целевые повторения
   - **Целевой вес** (вес, который клиент должен взять)
   - Время отдыха
   - Заметки и видео

#### **Во время тренировки:**
1. Наблюдает за клиентом (онлайн)
2. Использует `TrainerWorkoutLogger` для записи **фактического** выполнения:
   - Реальное количество повторений в каждом подходе
   - Реальный вес, который взял клиент
   - RPE (может корректировать)
   - Общие комментарии

### **🏃 Клиент:**

#### **До тренировки:**
1. Открывает дашборд (`ClientWorkoutView`)
2. Видит всю программу на неделю
3. Видит сегодняшнюю тренировку
4. Может подготовиться:
   - Понять какие упражнения будут
   - Взять нужную экипировку
   - Одеться удобно

#### **Во время тренировки:**
1. **НЕ ЗАПИСЫВАЕТ** веса и повторения
2. Может отметить только **RPE** (субъективную оценку нагрузки 1-10)
3. Фокусируется на выполнении, а не на записи

## 🎯 Компоненты

### **1. `ProgramConstructor.tsx`** (для тренера)

**Где:** Модальное окно в дашборде тренера  
**Цель:** Создание программы тренировок

**Функции:**
- Добавление недель
- Добавление тренировок по дням
- Добавление упражнений с:
  - Целевым весом
  - Целевыми подходами/повторениями
  - Заметками
  - Видео
- Сохранение в JSONB формате

### **2. `ClientWorkoutView.tsx`** (для клиента)

**Где:** Модальное окно в дашборде клиента  
**Цель:** Просмотр программы

**Функции:**
- Показывает все недели программы
- Выделяет тренировку сегодня
- Отображает по дням:
  - Все упражнения
  - Целевые параметры (подходы/повторения/вес)
  - Время отдыха
  - Заметки тренера
  - Видео техники

### **3. `TrainerWorkoutLogger.tsx`** (для тренера)

**Где:** Дашборд тренера (будет добавлено)  
**Цель:** Запись фактического выполнения

**Функции:**
- Загружает целевую программу
- Отображает форму для записи:
  - Фактических повторений каждого подхода
  - Фактического веса каждого подхода
  - RPE каждого подхода
- Общие заметки о тренировке
- Длительность
- Сохранение в `workout_sessions`

## 🔄 Типичный workflow

### **Этап 1: Планирование (за неделю до)**

```
Тренер → [ProgramConstructor]
  ↓
workout_programs (JSONB)
  ↓
[ClientWorkoutView]
  ↓
Клиент видит программу
```

### **Этап 2: До тренировки (утром)**

```
Клиент открывает дашборд
  ↓
ClientWorkoutView показывает:
  - "Тренировка сегодня: Upper Body"
  - Bench Press: 4x8-10, 80 кг
  - Dumbbell Press: 3x10-12, 30 кг
  - ...
  ↓
Клиент понимает что взять в зал
```

### **Этап 3: Во время тренировки**

```
Тренер (онлайн) наблюдает за клиентом
  ↓
Тренер открывает [TrainerWorkoutLogger]
  ↓
Клиент делает подход:
  - Bench Press, 80кг x 10 раз
  ↓
Тренер записывает в форму:
  - Подход 1: 10 повторений, 80 кг, RPE 7
  ↓
...следующие подходы...
  ↓
После тренировки:
Тренер → "Сохранить тренировку"
  ↓
workout_sessions создан
```

### **Этап 4: Анализ**

```
Тренер смотрит историю:
  - Целевой вес: 80 кг
  - Фактический вес: 80, 82.5, 82.5, 82.5 кг
  - Повторения: 10, 8, 8, 6
  ↓
Анализ: клиент прогрессирует, взял вес больше
  ↓
Корректирует следующую программу: 82.5 кг
```

## ✅ Преимущества такой логики

1. **Клиент не отвлекается** - не нужно записывать во время тренировки
2. **Точные данные** - тренер видит реальное выполнение
3. **Контроль техники** - тренер следит за формой
4. **Гибкость** - тренер может корректировать веса on-the-fly
5. **Безопасность** - тренер видит если клиент взял слишком большой вес
6. **Мотивация** - клиент не думает о записи, а фокусируется на выполнении
