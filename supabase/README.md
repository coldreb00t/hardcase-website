# HARD CASE - Supabase Backend Documentation

**Version:** 1.0.0
**Compatible with:** Web (Next.js), iOS (Swift), Android (Kotlin)

---

## Overview

This is the complete backend infrastructure for the HARD CASE personal training platform. The database schema is designed to support:

- **Web Dashboard** (Next.js) - for trainers and clients
- **iOS App** (Swift/SwiftUI) - for clients
- **Android App** (Kotlin/Compose) - for clients

All platforms share the same database, authentication, storage, and business logic.

---

## Architecture

```
Supabase Backend
├── PostgreSQL Database (single source of truth)
├── Authentication (email/password + magic links)
├── Storage (photos, videos, files)
├── Realtime (chat, notifications)
└── Edge Functions (business logic)
        ↓
┌───────┴──────┬──────────┬───────────┐
Web (Next.js)  iOS App    Android App  Admin
```

## Database Schema

### Core Tables

#### `profiles`
User profiles extending `auth.users`
- **Purpose:** Store user information (trainers and clients)
- **Key fields:** `role`, `full_name`, `phone`, `avatar_url`
- **Relations:** Referenced by almost all other tables

#### `trainer_client_relationships`
Maps which trainers work with which clients
- **Purpose:** Access control and relationship management
- **Key fields:** `trainer_id`, `client_id`, `status`
- **Used for:** RLS policies, permissions

#### `client_measurements`
Body measurements and composition data
- **Purpose:** Track physical progress (weight, body fat, etc.)
- **Key fields:** `weight`, `body_fat_percentage`, `measurements` (JSONB)
- **Updated by:** Trainers during check-ins

### Workout Tables

#### `workout_programs`
Training programs created by trainers
- **Purpose:** Store workout plans for clients
- **Key fields:** `program_data` (JSONB with exercises), `status`, `goals`
- **Flexible structure:** Supports any workout format

#### `workout_sessions`
Individual workout logs
- **Purpose:** Track workout completion and performance
- **Key fields:** `exercises_completed`, `duration_minutes`, `total_volume_kg`
- **Logged by:** Clients in mobile apps

#### `activity_logs`
Daily activity tracking (steps, sleep, heart rate)
- **Purpose:** Holistic health monitoring
- **Key fields:** `steps`, `sleep_hours`, `heart_rate_zones`, `recovery_score`
- **Data sources:** HealthKit, Google Fit, manual input

### Nutrition Tables

#### `nutrition_targets`
Daily macro targets set by trainers
- **Purpose:** Define nutrition goals (based on Harvard methodology)
- **Key fields:** `calories`, `protein_grams`, `fats_grams`, `carbs_grams`
- **Valid for:** Date range (`valid_from`, `valid_until`)

#### `nutrition_logs`
Food intake logs with photos
- **Purpose:** Track daily nutrition
- **Key fields:** `calories`, macros, `photo_urls` (array)
- **Integration:** FatSecret API, photo logging

### Progress Tracking

#### `progress_photos`
Before/after photos
- **Purpose:** Visual progress tracking
- **Key fields:** `photo_type`, `photo_url`, `tags`, `is_public`
- **Storage:** Supabase Storage buckets

#### `monthly_reports`
Comprehensive progress reports
- **Purpose:** Monthly summary by trainers
- **Key fields:** `weight_change_kg`, `workout_completion_rate`, `achievements`
- **Generated by:** Trainers or automated Edge Functions

### Communication

#### `conversations`
Chat conversations (trainer-client)
- **Purpose:** 1-on-1 messaging
- **Key fields:** `last_message_at`, `unread_count_trainer`, `unread_count_client`
- **Realtime:** Subscriptions enabled

#### `messages`
Individual chat messages
- **Purpose:** Real-time messaging
- **Key fields:** `content`, `message_type`, `attachment_url`, `read_at`
- **Supports:** Text, images, files

#### `appointments`
Scheduled video consultations
- **Purpose:** Booking system for trainer-client calls
- **Key fields:** `scheduled_at`, `duration_minutes`, `video_link`, `status`
- **Features:** Conflict detection, reminders

## Row Level Security (RLS)

All tables have RLS enabled. Key policies:

### Clients can:
- ✅ View their own data (profiles, workouts, nutrition, etc.)
- ✅ Create/update their own logs (sessions, nutrition, photos)
- ✅ View their trainer's profile
- ❌ Access other clients' data

### Trainers can:
- ✅ View their clients' data
- ✅ Create/update programs, targets, measurements for their clients
- ✅ Send messages to their clients
- ❌ Access clients they're not assigned to

### Security Principles:
- **Authenticated users only** - No public access to sensitive data
- **Isolation** - Clients cannot see each other's data
- **Trainer access control** - Based on `trainer_client_relationships`

## Setup Instructions

### 1. Create Supabase Project

```bash
# Go to https://supabase.com
# Create new project
# Note your Project URL and anon/public API key
```

### 2. Run Migrations

```bash
# In Supabase Dashboard > SQL Editor
# Run migrations in order:

1. 20250101000000_create_core_tables.sql
2. 20250101000001_create_workout_activity_tables.sql
3. 20250101000002_create_nutrition_progress_tables.sql
4. 20250101000003_create_messaging_appointments_tables.sql
5. 20250101000004_enable_rls_policies.sql
```

### 3. Configure Storage Buckets

Create these buckets in **Supabase Dashboard > Storage**:

- `profile-photos` (private) - User avatars
- `progress-photos` (private) - Body progress photos
- `nutrition-photos` (private) - Food photos
- `workout-videos` (private) - Exercise videos
- `report-attachments` (private) - Monthly report files

**RLS Policies for Storage:**

```sql
-- Users can upload to their own folder
CREATE POLICY "Users can upload own files"
ON storage.objects FOR INSERT
WITH CHECK (bucket_id = 'profile-photos' AND auth.uid()::text = (storage.foldername(name))[1]);

-- Users can view their own files
CREATE POLICY "Users can view own files"
ON storage.objects FOR SELECT
USING (bucket_id = 'profile-photos' AND auth.uid()::text = (storage.foldername(name))[1]);
```

### 4. Environment Variables

Add to `.env.local` (Next.js):

```bash
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

### 5. Install Dependencies

```bash
npm install @supabase/supabase-js @supabase/auth-helpers-nextjs
```

## Usage Examples

### Next.js (Web)

```typescript
import { supabase } from '@/lib/supabase'

// Fetch user's workout programs
const { data: programs } = await supabase
  .from('workout_programs')
  .select('*')
  .eq('status', 'active')

// Create nutrition log
const { data } = await supabase
  .from('nutrition_logs')
  .insert({
    client_id: clientId,
    date: '2025-01-26',
    meal_type: 'breakfast',
    calories: 450,
    protein_grams: 30,
    fats_grams: 15,
    carbs_grams: 50,
  })

// Realtime subscription for messages
supabase
  .channel('messages')
  .on('postgres_changes', {
    event: 'INSERT',
    schema: 'public',
    table: 'messages',
    filter: `conversation_id=eq.${conversationId}`,
  }, (payload) => {
    console.log('New message:', payload.new)
  })
  .subscribe()
```

### iOS (Swift)

```swift
import Supabase

let supabase = SupabaseClient(
  supabaseURL: URL(string: "https://your-project.supabase.co")!,
  supabaseKey: "your-anon-key"
)

// Fetch activity logs
let logs: [ActivityLog] = try await supabase
  .from("activity_logs")
  .select()
  .eq("client_id", clientId)
  .order("date", ascending: false)
  .limit(30)
  .execute()
  .value

// Upload progress photo
let imageData = image.jpegData(compressionQuality: 0.8)!
try await supabase.storage
  .from("progress-photos")
  .upload(
    path: "\(userId)/\(UUID().uuidString).jpg",
    file: imageData,
    options: FileOptions(contentType: "image/jpeg")
  )
```

### Android (Kotlin)

```kotlin
import io.github.jan.supabase.*
import io.github.jan.supabase.postgrest.*

val supabase = createSupabaseClient(
  supabaseUrl = "https://your-project.supabase.co",
  supabaseKey = "your-anon-key"
) {
  install(Postgrest)
  install(Auth)
  install(Storage)
}

// Fetch nutrition targets
val targets = supabase.from("nutrition_targets")
  .select()
  .eq("client_id", clientId)
  .single()
  .decodeAs<NutritionTarget>()

// Log workout session
supabase.from("workout_sessions")
  .insert(mapOf(
    "client_id" to clientId,
    "title" to "Upper Body Day",
    "status" to "completed",
    "duration_minutes" to 60
  ))
```

## Best Practices

### 1. Always use typed queries
```typescript
// Good ✅
const { data } = await supabase
  .from('profiles')
  .select<'*', Profile>('*')

// Bad ❌
const { data } = await supabase
  .from('profiles')
  .select('*') // No type safety
```

### 2. Handle errors properly
```typescript
const { data, error } = await supabase
  .from('workouts')
  .insert(workout)

if (error) {
  console.error('Database error:', error)
  throw new Error('Failed to create workout')
}
```

### 3. Use Edge Functions for complex logic
```typescript
// Instead of calculating in client:
const result = await supabase.functions.invoke('calculate-nutrition', {
  body: { userId, date }
})
```

### 4. Optimize queries with indexes
All foreign keys and frequently queried columns already have indexes.

## Troubleshooting

### Common Issues

**RLS Error: "new row violates row-level security policy"**
- Check that the user is authenticated
- Verify RLS policies allow the operation
- Ensure trainer-client relationship exists

**"relation does not exist"**
- Run migrations in correct order
- Check table name spelling (case-sensitive)

**Images not loading**
- Verify storage bucket exists
- Check RLS policies on storage.objects
- Ensure correct file path format
